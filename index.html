🛡️ Integrated Cybersecurity Report: ESP32 Honeypot Project

1. Introduction & Concept

This project implements a sophisticated cybersecurity defense mechanism: a Honeypot deployed on an ESP32 microcontroller. The primary objective is to simulate a vulnerability (an open Wi-Fi access point) to lure, deceive, and analyze potential attackers or unauthorized users without exposing the actual production network.

This system is designed for real-time monitoring of connection attempts, logging interaction patterns, and displaying a 'Captures' count on an integrated OLED screen. By studying these interactions, we gain insights into attack vectors and network vulnerabilities.

Key Protocols Used:
  • HTTP: To serve the Captive Portal page to connected clients.
  • DNS: For DNS Spoofing, redirecting all traffic to the local server.
  • I2C: For high-speed communication between the ESP32 and the OLED display.

2. Technical Architecture (Hardware)

The hardware setup is designed for portability and efficiency. We utilize the ESP32 for its robust dual-core processing and integrated Wi-Fi capabilities.

Figure 1: ESP32 & OLED Pinout Diagram with technical annotations.

  • ESP32 Microcontroller: Manages the Access Point and Web Server.
  • SSD1306 OLED Display: Provides real-time visual output of system status and captured data.
  • I2C Wiring: SDA connected to GPIO 21, SCL connected to GPIO 22.

3. Embedded Software (Logic)

The code is developed in C++ using the Arduino framework. It manages the Wi-Fi stack, handles DNS queries, and serves a custom-designed login page.

Figure 2: Software execution flow and library integration.

The software utilizes the DNSServer library to intercept all web requests, forcing the device to display the Captive Portal. The WebServer library then handles the form data submission from the victim's device.

4. Cybersecurity Risk Analysis (Scenarios)

This project illustrates the risk of an 'Evil Twin' attack. The scenario unfolds as follows:

  1. Deception: The attacker sets up a free Wi-Fi network (e.g., "Airport_Free_WiFi").
  2. Connection: An unsuspecting user connects to the open network.
  3. Redirection: The Honeypot immediately serves a deceptive 'Login' page.
  4. Data Capture: The user submits credentials, which the Honeypot intercepts and displays on the OLED screen.
Educational Goal: To demonstrate the critical need for VPNs and the danger of using unencrypted public networks.

5. Results & Final Deployment

The system successfully creates a stable access point and intercepts connection attempts seamlessly. The OLED display provides real-time monitoring of captured credentials and total capture count.

Figure 3: Final System Prototype in operation.

Conclusion: This project successfully demonstrates practical embedded systems integration for cybersecurity education and threat analysis.
