04. Problem Statement

خلال بحثي، وجدت أن المشكلة الحقيقية تكمن في "العمى الأمني". مضادات الفيروسات الحالية تشبه الشرطي الذي يبحث عن المجرمين من خلال صورهم فقط؛ إذا غير المجرم وجهه (أو غير الفيروس كوده)، فلن يتعرف عليه أحد. هذه هي ثغرات Zero-Day التي تستغلها الدول والجماعات التخريبية.

"التحدي هو: كيف نكتشف الهجوم إذا كان كوده البرمجي نظيفاً تماماً؟ الإجابة هي مراقبة التأثير لا المحتوى."

The lag time between an exploit's discovery and its patch is the most dangerous period in cybersecurity. My goal is to eliminate this lag entirely.

09. Practical Implementation

لقد قمت باختيار لغة JavaScript (Node.js) لتطبيق الجانب العملي. السبب بسيط: مرونة هذه اللغة في التعامل مع "أحداث النظام" (System Events). الكود أدناه يمثل نموذجاً أولياً قمت بكتابته لمراقبة استهلاك المعالج وتصرفات العمليات النشطة، وهو ما يمثل النواة البرمجية لمشروعي.

// Sentinel Monitor v1.0 - Karrar Mohammed
const os = require('os-utils');

function watchBehavior() {
  os.cpuUsage((usage) => {
    if (usage > 0.92) {
      console.log("CRITICAL: Suspicious Behavioral Spike Detected!");
      triggerIsolationProtocol();
    }
  });
}

setInterval(watchBehavior, 1000); // Monitoring every second

هذا الكود هو تطبيق لما نسميه "Behavioral Threshold". من خلاله، استطعت في مختبري الشخصي اكتشاف هجمات تجريبية قمت بصنعها بنفسي، وكانت النتائج مبهرة ودقيقة.
